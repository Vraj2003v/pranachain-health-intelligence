# Kickoff alignment

The six deliverables from the kickoff brief (`README.md`, Deliverables), where each one lives in the repository or the app, and what is still a gap. Every path below exists on `main`.

| Kickoff deliverable | Where it lives | Still a gap |
|---|---|---|
| **Working prototype**: end-to-end flow on synthetic or anonymized longitudinal data | React app in `web/src/` served by the FastAPI backend in `api/main.py`, with the detection code in `pranapulse/`. In the app: **Try demo patients**, then the five steps Understand, Connect, Detect, Explain, Ask (`web/src/components/Steps.jsx`). Demo flow: `docs/demo-script.md` | Runs locally or in Codespaces only; it has not been deployed for outside users. |
| **AI/data approach**: data structuring, connection over time, reasoning choices | `docs/data-schema.md` (verified workbook layout), `pranapulse/loader.py` (reading the workbooks), `docs/three-approaches.md` (one method, three areas), `docs/architecture.md`, and Reasoning choices in `docs/limitations-and-next-steps.md` | Two workbook sheets (Habits Weekly, Symptoms Timeline) are not read yet; clinical notes and medication adherence are read as context only. |
| **Explainable output**: contributing data, link to history, uncertainty and limitations per insight | Each finding in the app has **Why was this flagged? Supporting evidence**, with evidence IDs and the dates, averages and days with data (`web/src/components/Insights.jsx`, `pranapulse/detect.py`). Data-sufficiency flags and the wording check are in `pranapulse/explain.py` | History is linked to findings as context only; it does not change what is detected. |
| **Validation**: tested against all three scenarios | `docs/results/validation_summary.md` and `docs/results/history_consistency.md` (900 workbooks), `scripts/validate_scenarios.py`, `tests/test_sections.py`, `tests/test_disease_inputs.py`, assistant safety in `docs/safety-test-results.md` (22 Nov re-run: 150 of 150 safety questions got the fixed safe answer), demo check in `scripts/demo_check.py` with `tests/test_dataset_pcos.py` | Data is synthetic and thresholds are placeholders, so the results show consistency, not clinical accuracy. Cardiovascular findings do not yet separate people with related history from those without. |
| **User experience**: a dashboard, timeline or interface that makes output understandable | Summary, findings, timeline and assistant screens (`web/src/components/Dashboard.jsx`, `Timeline.jsx`, `ChatDock.jsx`), `docs/user-guide.md`, and the interface review with screenshots in `docs/ui-review.md` | Not tested with real patients or clinicians. |
| **Technical handoff**: source code, setup, architecture, assumptions, limitations, next steps | Code in `pranapulse/`, `api/`, `web/` and `tests/`. Setup: "Start here: set up from a fresh clone" in `README.md` and `.devcontainer/`. Architecture: `docs/architecture.md`. Limitations and next steps: `docs/limitations-and-next-steps.md` | `docs/architecture.md` still has early sections marked "not yet decided" that were later settled in other files. |
